# UI Spec — Logs Tab Tile "1a: Card Overview"

Custom web resource for a Dataverse model-driven app form tab ("Logs"). Replaces three editable subgrids (Risks, Project Dependencies, Change Request Log) with three overview tiles. **Tiles are read-only overviews; clicking a tile (or its "Open view" link) navigates to the standard associated view/subgrid.** No inline editing, no "+ New" on tiles.

## Global

- Font: `"Segoe UI", system-ui, -apple-system, sans-serif` (native MDA look)
- Page background: `#f3f2f1` (transparent also acceptable inside the form tab)
- Text primary: `#323130` · secondary: `#605e5c` · tertiary/meta: `#8a8886`
- Brand red: `#c8102e` · red hover: `#a50d26` · red tint bg: `#fbeaed` · red tint border: `#f2c6cd`
- Greys: border `#e1dfdd` · hairline `#edebe9` / `#f3f2f1` · bar greys `#8a8886`, `#b8b6b4`, `#d9d7d5` · subtle bg `#faf9f8`
- Links: red `#c8102e`, no underline; hover `#a50d26` + underline

## Page header (above tiles)

Flex row, baseline-aligned, gap 12px, margin-bottom 14px:
1. Title "Project Logs" — 16px / 600
2. Subtitle — 12px, `#605e5c`: "Overview of related Risks, Dependencies and Change Requests"
3. Right-aligned (margin-left auto): "Refreshed HH:MM" — 12px, `#8a8886`

## Tile layout

- Container: `display:flex; gap:16px; flex-wrap:wrap; align-items:stretch`
- Each tile: `flex:1; min-width:300px` (3-across on desktop, wraps on narrow forms)

## Tile anatomy (top → bottom, vertical flex, gap 12px)

Card: white bg, `1px solid #e1dfdd` border, radius 6px, padding `16px 18px`, `cursor:pointer`, entire card clickable → opens associated view.
Hover: `border-color:#c8102e; box-shadow:0 2px 8px rgba(200,16,46,0.12)`.

### 1. Header row (flex, gap 10px, center-aligned)
- Monogram: 28×28px, radius 4px, bg `#f3f2f1`, letter 13px/700 `#605e5c` — "R" / "D" / "C"
- Entity name: 14px / 600
- Alert chip, right-aligned (margin-left auto): 11px/600, padding `2px 9px`, radius 10px.
  - Urgent variant (red): color `#c8102e`, bg `#fbeaed`, border `1px solid #f2c6cd` — e.g. "3 high severity", "1 blocked"
  - Neutral variant (grey): color `#605e5c`, bg `#f3f2f1`, border `1px solid #e1dfdd` — e.g. "4 in review"
  - Chip rules: show the single most urgent condition; hide chip when count is 0.

### 2. Count + trend row (flex, bottom-aligned, gap 8px)
- Total count: 34px / 600, line-height 1
- Label "records": 12px, `#605e5c`, 3px bottom padding
- Mini trend (right-aligned): 8 bars = new records per week, last 8 weeks. Bars: 6px wide, 2px gap, max height 26px, radius 1px, heights proportional. Colors: oldest 5 bars `#d9d7d5`, next 2 `#b8b6b4`, current week `#c8102e`. Tooltip/title: "New records, last 8 weeks".

### 3. Status distribution bar
- 6px tall, radius 3px, `overflow:hidden`, track bg `#f3f2f1`
- Segments with width % = share of records, ordered most→least urgent
- Segment colors by urgency rank: 1st (worst) `#c8102e`, then `#e08a99` (only if 4+ statuses or a "warning" tier exists), `#8a8886`, `#b8b6b4`, lightest/done `#d9d7d5`

### 4. Legend row (flex, gap 14px, wrap; 12px, `#605e5c`)
- One item per status: 8px dot (same color as its segment) + "Label · N"

### 5. Latest-record strip
- 12px, `#605e5c`, bg `#faf9f8`, border `1px solid #edebe9`, radius 4px, padding `7px 10px`
- Content: "Latest: [record name as red link] · [relative age, e.g. 2 d ago]" — link opens that record's form

### 6. Footer (flex, center-aligned, gap 10px; top hairline `1px solid #f3f2f1`, padding-top 10px)
- Owner avatar stack: distinct owners of active records, max 3 + implicit overflow. 24px circles, initials 10px/700 white, `2px solid #fff` border, overlap `margin-left:-7px`. Bg colors cycle: `#c8102e`, `#605e5c`, `#8a8886`.
- "Updated [n] ago" — 11.5px, `#8a8886` (relative time since newest `modifiedon` across related records)
- Right-aligned: "Open view ↗" — 12px/600 red link → associated view (same as card click)

## Per-tile content mapping

| | Risks | Project Dependencies | Change Request Log |
|---|---|---|---|
| Monogram | R | D | C |
| Alert chip | "N high severity" (red) | "N blocked" (red) | "N in review" (grey) |
| Statuses (urgent→done) | Open / Mitigated / Closed | Blocked / At risk / On track | Rejected / In review / Submitted / Approved |
| Latest record | newest by createdon | newest by createdon | newest by createdon (prefix CR number) |

Note: status values above are placeholders — map to the real option sets; keep the urgency ordering rule (worst status gets red).

## Data (Dataverse)

- Counts + status breakdown: one aggregate FetchXML per entity via `Xrm.WebApi.retrieveMultiple` (count grouped by status option set), filtered to the current record (`Xrm.Page`/form context id as the lookup filter)
- Latest record + last-updated: top-1 query ordered by `createdon` desc / `modifiedon` desc
- Owners: distinct `ownerid` of non-closed records (top 3)
- Navigation: `Xrm.Navigation.navigateTo({pageType:"entitylist"...})` or open the related view via form context; record link → `Xrm.Navigation.openForm`
- Empty state: count 0 → bar hidden, legend replaced by "No related records", chip hidden, footer keeps "Open view ↗"

## Accessibility

- Tile is a single interactive element: `role="link"`, `tabindex="0"`, Enter/Space activates; inner links (latest record) stop propagation
- All status info is text+dot, never color-only; contrast: red on white and greys ≥ 4.5:1 at given sizes
